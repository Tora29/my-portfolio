俺「作業よろしく！」
Claude「かしこまりました。エージェントを起動して作業を並列で進めます。（エージェント複数起動）」
俺「はて、誰が何やってんだ、、？」

という感じで、サブエージェントが並列に動き出すと、どのエージェントが何をしていて、どこで止まっているのかが見えにくくなります。

そこで、エージェント 1 つを猫 1 匹に見立てて、その様子をターミナルの全画面に描く **ねこエージェント**（neko-agents）を作りました。動くと、こんな感じです。

![ボスが「手分けして調べるニャ」と言って子猫のソラとミケを起動する。2 匹はボスの部屋で依頼を受け取ってから自分の部屋へ歩いて戻り、作業する。終わったソラは「useAuth が 2 か所で重複してたニャ！」と言いながらボスの部屋へ報告に行き、続いてミケも「テストも通ったニャ！」と報告する](/images/claude-code-neko-agents/flow.webp)

メインのエージェントが親猫の「ボス」、サブエージェントが子猫です。子猫は自分の部屋で作業し、終わるとボスの部屋まで歩いて報告に行きます。

Claude Code のプラグインマーケットプレイスとして公開しているので、`claude plugin install` で入れられます。ソースコードは [GitHub](https://github.com/Tora29/my-claude-tools) にあります。

この記事では、ねこエージェントの見方と使い方を紹介したあと、Mod（Claude Code の function hooks 型のプラグイン）として作るときに工夫したことも書きます。

## 何に困っていたか

サブエージェントを何匹も、、いや何個も並列に走らせると、Claude Code の画面だけでは次のことが分かりにくくなります。

- いま、どのエージェントが動いていて、どれが終わったのか
- 誰が誰に頼まれた仕事なのか
- 許可や回答を待って止まっているのは、どのエージェントか

特に困るのが最後のものです。ほかのタブで作業していると、許可待ちで止まっていることに気づかず、戻ってきたら何も進んでいなかった、、ということがあります。

## ねこエージェントの見方

猫 1 匹（エージェント 1 つ）につき、部屋（箱）が 1 つあります。Claude Code のタブ（セッション）ごとに「── プロジェクト名」の区画に分かれて、縦に並びます。

![ねこエージェントの画面。my-portfolio と my-claude-tools の 2 つのタブの区画に、ボス猫と子猫の部屋が木の形に並んでいる。Bash の許可を待つ子猫のモモの枠が赤く光り、ハチは線の上を歩いてボスへ報告に向かっている](/images/claude-code-neko-agents/overview.webp)

上の図は、2 つのタブの猫を並べた画面です。線の上にいる `=^.^=` は、ボスへ報告に向かっているハチです。

### 線と移動

実線は依頼の親子関係で、点線はそれ以外のつながりです。点線は次の 3 種類で、エージェントの動きから推測して引いています。

| つながり | 引く条件 |
| --- | --- |
| 引き継ぎ | 前の子猫が完了した後に、次の子猫が起動された（結果を受け取ったとみなす） |
| レビュー | ほかの猫が書いたファイルを Read した |
| お手紙 | SendMessage を送った |

猫はこの線の上を歩いて、ほかの猫の部屋を行き来します。起動した子猫は、親の部屋で依頼を受け取ってから自分の部屋へ帰ります。終わった子猫は、親の部屋へ報告に行きます。出かけている間、自分の部屋は「留守」になります。

![ソラが「見つけたニャ！」と言いながら線の上を歩いてボスの部屋へ報告に行き、クロが「お手紙ニャ」と言いながら点線の上を歩いてミケの部屋へ向かっている。2 匹の部屋は留守になっている](/images/claude-code-neko-agents/walking.webp)

### ポーズと枠の色

猫のポーズで状態が分かります。毛色は名前で決まり、ボスはどのタブでも茶トラです。

![ねこ図鑑。ポーズは、作業中は手がパタパタ、おやすみは頭の上に zzz、許可待ちは枠が赤く点滅、完了はにっこり、失敗はしょんぼり、中断は空の箱、お出かけ中は部屋が留守、歩く猫は線の上を移動する。毛色は茶トラ・白・黒・三毛・ハチワレ・灰色・茶色の 7 種類で、それぞれの色になる名前が並んでいる](/images/claude-code-neko-agents/dex.webp)

許可を待っている猫は、箱の枠が赤く点滅し、2 行目が「? Bash の許可待ち」になります。ほかのタブで作業していても、視界の端で赤く光っていれば気づけます。

![子猫のモモの枠が赤く光り、「? Bash の許可待ち」「これやっていいニャ？」と表示されている。隣のトラは Read を実行中で、ボスは「ひまニャ…」と言っている](/images/claude-code-neko-agents/permission.webp)

猫はときどきしゃべります。起動したときは「いってくるニャ！」、ツールがエラーになったときは「あれ？おかしいニャ」のように、状況に合ったことを言います。長引くと「めんどくさいニャ…」とぼやきます。子猫たちが働いている間、暇なボスは「ひまニャ…」と退屈しています。

## 猫が報告し、質問を解説してくれる

### 結果を猫口調の 1 文にする

子猫が終わると、結果を Claude Haiku で猫口調の 1 文に要約して報告します（例：「useAuth が重複してたニャ！」）。子猫を使った作業がひと区切りつくと、ボスがその作業を 1 文にまとめます（例：「useAuth の重複を見つけて直したニャ」）。

サブエージェントの結果は長いことが多いので、1 文で「何が分かったか」だけ先に知れると、どの結果を読み込むべきか判断しやすくなります。

![作業が終わって眠るボスの下に、完了したソラとミケ、失敗したクロが並んでいる。図の下に「ボスのまとめ：useAuth の重複を hooks/ にまとめて、テストも通したニャ」と出ていて、その下に質問の記録が新しい順に並び、選んだ答えに ✔ が付いている](/images/claude-code-neko-agents/summary.webp)

### 質問を解説する

Claude が AskUserQuestion で質問してくると、質問した猫の枠が赤く点滅し、図の下に猫口調の解説が出ます。解説は次の 4 つの節に分かれています。

- いまの指示
- なぜ聞いているか
- 選択肢ごとの影響
- おすすめ

並列で作業していると、質問が来たときに「そもそも何の話だっけ？」となりがちです。解説を読めば、会話をさかのぼらずに答えを決められます。

**Special Thanks：[qa-guide](https://github.com/aieo-product/claude_qamods)（作者：[syn-otani](https://github.com/syn-otani) さん）**

解説の中身は、qa-guide をほぼそのまま使わせてもらっています。ねこエージェントの解説が分かりやすいのは、qa-guide のおかげです、、！
:::

![ボスの枠が赤く光り「回答待ち「寄せる先」」と出ている。図の下に、いまの指示・なぜ聞いているか・選択肢ごとの影響・おすすめの 4 節が色分けされて並び、ソラの調査結果をもとに「1. hooks/ に寄せる」がおすすめされている](/images/claude-code-neko-agents/question.webp)

解説には、手伝っている子猫たちの結果も使います（例：「ソラが調べたら useAuth が重複してたから、1 がおすすめニャ」）。回答待ちの間に子猫が終わったら、その報告を足して解説を作り直します。作り直した解説の冒頭には「ソラの報告が来たから考え直したニャ」と出ます。

## 使い方

```sh
# Mod を入れる（どの Claude Code でも猫が記録されるようになる）
claude plugin marketplace add Tora29/my-claude-tools
claude plugin install neko-agents@my-claude-tools

# ビューアのコマンドを入れる（Bun が必要）
git clone https://github.com/Tora29/my-claude-tools.git
cd my-claude-tools && bun link

# ビューアを開く（ターミナルの別タブや分割した画面で）
neko-agents
```

`bun link` で入れたコマンドは `~/.bun/bin` に置かれるので、ここにパスが通っている必要があります。

ビューアは `q` で終了します。猫の箱をクリックすると、その猫がやっていること・誰からの依頼か・最近の操作などの詳細が、画面の下に出ます。

![子猫のミケの箱をクリックした画面。箱の枠が水色になり、画面の下に、いまの様子・ボスからの依頼・最近の操作が新しい順に並んでいる](/images/claude-code-neko-agents/detail.webp)

要約と解説は、`/config` の neko-agents からそれぞれオフにできます。要約は 1 回あたり数百トークン、解説は数千トークンを使います。

## 仕組み

### 記録係と表示係に分ける

neko-agents は、記録係の Mod と表示係のビューアの 2 つでできています。プラグインとして入れるのが Mod で、`neko-agents` コマンドで開くのがビューアです。

![ねこエージェントのしくみ。各タブの Claude Code の中で動く Mod が、hooks のイベントから猫の状態を作り、タブごとの部屋のファイルに書き出す。別のターミナルで動くビューアが、0.2 秒ごとに全タブ分のファイルを読んで、1 つの画面に描く](/images/claude-code-neko-agents/architecture.webp)

Mod は Claude Code の function hooks 型のプラグインで、ビューアは Bun で動くプログラムです。

こう分けたのは、Mod が自分のタブのことしか知らないからです。

Mod は Claude Code のタブごとに 1 つずつ動き、受け取れるのはそのタブの hooks のイベントだけです。全タブの猫を 1 画面に並べるには、各タブの Mod が知っていることを、どこか 1 か所に集める必要があります。

そこで、Mod は自分のタブの部屋のファイルを書くだけにして、描くのは別のターミナルで動くビューアに任せました。ビューアは全タブのファイルを読むだけなので、タブが増えても減っても、何もしなくても全タブの猫が 1 画面に集まります。Mod は Claude Code の画面に何も描かないので、作業の邪魔にもなりません。

### hooks のイベントから猫の状態を組み立てる

Mod は、Claude Code の hooks のイベントを受けて猫の状態を更新します。

| イベント | 猫に起きること |
| --- | --- |
| `turn.start` | ボスが動き出す |
| `agent.spawn` | 子猫が生まれ、親の部屋で依頼を受け取る |
| `tool.call` | ツールの回数を数え、レビュー・お手紙の線を引く |
| `classic.PermissionRequest` | 許可待ちになり、枠が赤く点滅する |
| `turn.complete` | 子猫が完了・失敗し、親の部屋へ報告に行く |
| `session.end` | タブを閉じたことを書き出す |

たとえば、引き継ぎの点線は次のように決めています。親が新しい子猫を起動したときに、兄弟の中に直前の起動より後に完了した子猫がいれば、その結果を新しい子猫に渡したとみなします。

```ts:plugins/neko-agents/hooks/links.ts
/**
 * 引き継ぎ：親が新しい子猫を起動したとき、その前の起動より後に完了した兄弟は、
 * 結果を新しい子猫に渡したとみなす
 */
export function batonsFor(cats: readonly Cat[], parent: string, child: string): string[] {
  const ids = new Set(cats.map(cat => cat.id))
  const siblings = cats.filter(cat => cat.id !== child && !isBoss(cat) && parentOf(cat, ids) === parent)
  if (siblings.length === 0) return []
  const lastSpawn = Math.max(...siblings.map(cat => cat.startedAt))
  return siblings.filter(cat => cat.status === 'completed' && (cat.endedAt ?? 0) >= lastSpawn).map(cat => cat.id)
}
```

「調べる子猫が終わってから、直す子猫を起動する」ような流れを、エージェントに何も書かせずに線で表せます。あくまで推測なので、実際に結果を渡していないこともあります。

### 書き出しは控えめに

hooks のイベントはツールを呼ぶたびに届くので、そのたびにファイルを書くと無駄が多くなります。そこで、書き出しは次のようにまとめています。

- 変化があったときだけ、多くても 0.5 秒に 1 回書く
- 働いている猫がいる間は、変化がなくても 1 分に 1 回書き直して、生きていることを示す
- ビューアは、閉じたタブと 10 分以上更新のないタブを表示しない

```ts:plugins/neko-agents/hooks/register.ts
/** このタブの猫を書き出す。中身が変わっていなければ書かない（動いている間は 1 分ごとに生存確認だけ書く） */
async function writeRoom($: Dollar, closing?: string) {
  // …
  const key = session + contentKey(room)
  const busy = room.cats.some(cat => isActive(cat) || cat.trip)
  if (key === lastKey && !(busy && t - lastWriteAt >= HEARTBEAT_MS)) return
  await $.fs.write(roomFile(dir, session), JSON.stringify(room))
  lastKey = key
  lastWriteAt = t
}
```

Claude Code が落ちて「閉じた」と書けなかったタブも、更新が止まれば 10 分で消えます。猫が歩くアニメーションは、ファイルには行き先といまの段階（出発・到着・滞在・帰り道）、その段階が始まった時刻を書き、段階の中での位置はビューアが現在の時刻から計算しています。

### Haiku に送るものを絞る

要約と解説には、Mod から呼べるモデルの API（`$.model.complete`）で Claude Haiku を使っています。

解説を作るときに送るのは、ユーザーの最近の指示・直前の説明・その後のツール操作・質問・子猫の結果で、会話全体は送りません。トークンを抑えるためでもあり、質問に関係ない内容でおすすめがぶれないようにするためでもあります。

子猫の結果の本文は Mod の中だけに持ち、部屋のファイルには書き出しません。ファイルに出すのは、猫口調の要約と解説だけです。

### 描画のレイアウトをテストする

ビューアは、猫の箱の並べ方と線の引き方（レイアウト）を、ターミナルへの描画から切り離しています。レイアウトは「猫の一覧から文字の格子を作る」純粋な関数なので、Bun のテストで単体テストできます。

地味に大変だったのが文字の幅です。箱の中に日本語と記号が混ざるので、全角は 2 桁、半角は 1 桁として数えないと、枠がずれてしまいます。

## まとめ

- サブエージェントを並列に動かすと、誰が何をしていて、どこで止まっているかが見えにくい
- ねこエージェントは、エージェントを猫に見立てて、全タブの様子をターミナルの 1 画面に描く
- 許可待ち・回答待ちの猫は赤く点滅し、結果や質問は猫が 1 文や解説にまとめてくれる

弱点を挙げるなら、画面の場所を取ることです。ビューアはターミナルの全画面に描くので、別のタブか分割した画面を 1 つ、猫たちのために空けておく必要があります。（可愛いので許せますが、、笑）

並列に動くエージェントを見守るのが、ちょっと楽しくなりました。よければ試してみてください！
