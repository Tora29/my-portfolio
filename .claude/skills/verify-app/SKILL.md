# verify-app

アプリの動作を担保するチェックを順に実行し、結果を報告する。確認のみを行い、ユーザーに頼まれない限りコードは直さない。

## 実行するチェック

上から順に実行する。前のチェックが失敗しても、残りのチェックは続けて実行する（失敗をまとめて報告するため）。ただし、ビルドが失敗した場合は E2E テストを実行しない（E2E はビルド結果に対して動くため）。

| # | チェック | コマンド | 確認すること |
| --- | --- | --- | --- |
| 1 | フォーマット | `npm run format:check` | Prettier の書式に沿っているか |
| 2 | Lint | `npm run lint` | ESLint のエラーがないか |
| 3 | 単体テスト | `npm run test` | Vitest がすべて通るか |
| 4 | ビルド | `npm run build` | `astro check`（型・スキーマ）とビルドが通るか |
| 5 | E2E テスト | `npm run test:e2e` | 主要ページが表示されるか（Playwright） |
| 6 | 静的解析 | `npm run semgrep` | Semgrep の検出がないか |

- ユーザーが範囲を指定した場合（例：「E2E は省略」「Lint だけ」）は、指定されたチェックのみ実行する
- 依存が入っていない（`node_modules/` がない）場合は、先に `npm ci` を実行する
- Playwright のブラウザが入っていないエラーが出た場合は `npx playwright install chromium` を実行してから再実行する
- `semgrep` コマンドがない場合は、実行せず「`brew install semgrep` が必要」と報告する（失敗扱いにしない）
- E2E テストの前に `npx astro preview status` で preview が残っていないか確認し、残っていれば `npx astro preview stop` で止める（ポート 4321 の取り合いを防ぐ）

## 失敗したとき

- 出力から、失敗したファイル・行・エラー内容を抜き出す（出力全体は貼らない）
- 原因の見当がつく場合は、修正方針を一言添える
- フォーマットの失敗は `npm run format` で直せることを伝える。勝手に実行しない

## 報告

最後に次の形式でまとめる。

```text
| チェック | 結果 |
| --- | --- |
| フォーマット | ✅ |
| Lint | ❌ src/lib/foo.ts:12 'bar' is defined but never used |
| 単体テスト | ✅（12件） |
| ビルド | ✅ |
| E2E テスト | ⏭ ビルド失敗のため未実行 |
| 静的解析 | ✅（検出 0件） |
```

- すべて通った場合は「すべてのチェックが通りました」と一言添える
- 失敗がある場合は、コミットや PR 作成に進まないよう伝える
